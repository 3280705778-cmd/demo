2>查看username和useremail是否配置完成：
打开git bash输入git config user.name和git config user.email查看是否有结果，没有的话依次输入进行配置（与github账户一致）：
```
git config --global user.name 用户名
git config --global user.email  邮箱
```
3>创建SSH公钥以下载仓库：
在git bash里输入：ssh-keygen -t rsa -C "邮箱"

中间出现的所有停顿全部回车就可以（是设置密码的，但不需要）

打开C盘用户文件夹下的.ssh文件中的id_rsa.pub文件，记事本打开，其内容即为SSH公钥，复制到你的github账户，点击右上角头像->Settings->SSH and GPG keys->New SSH key->随便取个title，然后粘贴即可

验证：键入ssh -T git@github.com，然后停顿处输入yes

如果出现Hi 用户名! You've successfully authenticated, but GitHub does not provide shell access.即配置完成

## 1.什么是组织
GitHub组织是GitHub平台上的一个功能，允许用户将多个个人帐户、项目和团队集合在一起，以共同管理和协作开发。组织提供了一个集中的地方，让团队成员可以共享代码、管理项目、协作审查代码、分配任务等。

在GitHub组织中，可以拥有多个仓库，每个仓库可以包含不同的项目或代码库。组织内的成员可以根据他们的角色和权限，对不同的仓库进行访问、编辑和管理。这有助于确保团队成员之间的协作和代码的安全性。

**队内的组织HTML：https://github.com/WHUROBOCON**

## 2.什么是仓库
GitHub仓库是用于存储项目文件和版本历史的核心单元。每个仓库都可以看作是一个独立的代码库，其中包含了项目的所有文件、目录、提交历史以及相关的元数据。

仓库通常用于存放源代码、文档、配置文件等，并允许用户通过Git这样的版本控制系统来跟踪和管理这些文件的变化。通过Git，用户可以提交更改、查看历史记录、创建分支、合并代码以及与其他协作者进行协作。

**我们定义仓库的目的为给每一个独立的方案以一个独立的工作空间，不同的人负责同一个方案时就从同一个仓库中下载、更新代码**

## 3.什么是分支
分支是从主线上分离出来进行另外的操作的代码线。分支的存在既不影响主线，主线又可以继续其原有的工作流程。

分支的主要作用包括：
- 并行开发：每个分支都是代码的独立副本，可以并行推进多个功能的开发。
- 版本管理：分支使得版本管理变得更为轻松。当一个分支的代码稳定后，可以将其合并到主分支进行发布，而不会影响其他正在进行的开发工作。
- 故障隔离：如果在开发中遇到问题或发生错误，可以创建一个新分支来排查和修复问题，而不会影响其他分支的代码。

常见的分支类型包括：
- 主分支（main）用于存储正式发布的历史，所有的开发活动产生的输出物最终都会反映到主分支的代码中。主分支应该是经过充分测试和验证的代码，不能直接在主分支上进行开发，主分支上的代码必须是可行而没有bug的。
- 开发分支（dev）：用于整合和存放开发人员的工作成果。在这个分支上，开发人员可以自由地添加、修改和删除代码，进行新功能的开发或修复bug。

**我们定义分支的目的为给对应的方案一个绝对可以使用的版本main和一个测试中的版本dev，所有具有不确定性的实验性代码提交到dev分支中，在main中的代码必须是拿来就可以立即使用的，如果不同的人对于同一个方案有不同的实验性代码，规定命名格式为：人名_dev**

## 4.我怎么向组织首次发布我的代码？
在组织中新建一个仓库，以对应的功能命名，**注意这里命名必须为英文**（建议设为私有，即只有组织内成员可见）

本地电脑新建或找一个文件夹用于存放仓库，先克隆你创建的仓库的对应分支：（此时由于仓库和分支都是空的，对应分支应当只有main分支）
```
git clone -b 分支名(main) git@github.com:WHUROBOCON/仓库名.git
```
git clone的目的是将你本地的文件夹和远端的仓库建立关系，为之后的push/pull等操作确定目标

记得**一定要进入有.git的文件夹**，一般是你新建的文件夹下的子文件夹，不然会报错：not a git repository

将整个Keil工程除.git文件夹的所有文件复制到这个文件夹中（可以写个readme方便他人阅读代码功能）

请再次确认要上传的所有文件里只存在一个.git文件夹，不然会报错：does not have a commit checked out

接着就可以上传文件了，在仓库文件夹下的git bash中依次键入：
```
git add .            //警告不用管
git commit -m "更新信息"
git push             //第一次上传可能需要git push --set-upstream origin 分支名 以建立远程连接
```
这样子新的仓库里就有你的代码了！！

## 5.我怎么向组织发布我修改后的代码？
首先请确认你修改代码的目的是更新main分支还是dev分支，如果需要创建一个新分支以存放代码，方法如下：

新建一个自己的分支，在原仓库文件夹的git bash中依次键入：（这一步也可以直接在github上完成，但由于缓存更新不及时的原因不推荐）
```
git branch 新分支名         //在本地创建分支
git push origin --all      //将分支push到远端仓库
git checkout 新分支名       //切换到新分支下
```
如果不需要创建一个新分支，那么直接使用git checkout切换到对应分支即可

确认好自己发布的目标分支，在仓库文件夹下的git bash中依次键入：
```
git add .
git commit -m "更新信息"
git push            //第一次上传可能需要git push --set-upstream origin 分支名 以建立远程连接
```
**注意：这次更新只会上传到你所在的分支，其他分支的文件并不会发生改变**

同样的，记得确认要上传的所有文件里只存在一个.git文件夹

## 6.我怎么将完善好的dev分支覆盖到可用的main分支中？
使用git checkout调整分支到被合并的分支名称(main)下，在git bash中键入：
```
git merge 需要保留的分支(dev)
```
此时在本地dev分支就已经将main分支覆盖了，但是**为了让远端仓库同步这一操作，需要再进行一次git push**

这样就可以把需要保留的分支(dev)中的内容覆盖到被合并的分支(main)中去了

## 7.我怎么从组织中下载需要的代码？
本地电脑新建一个文件夹存放仓库，在仓库文件夹下的git bash中键入：

`git clone -b 分支名 git@github.com:WHUROBOCON/仓库名.git`

这样就可以将对应仓库对应分值的代码下载到你本地的文件夹中，如果只是临时的测试人员，只需要下载main分支中的代码就可以了！下载好后就可以像往常一样使用啦！

值得注意的是，**通过这种方法你只能获取整个仓库文件的某一个分支及其内容（建议为main分支），我们希望通过这个方式阻止代码在不同的dev分支中流窜**

## 8.我怎么获取最新的仓库？
当有人更新你clone下来的仓库时，请及时获取最新的仓库信息，一般建议**每次要写新东西或使用前主动进行一次更新**，避免版本落后。

在仓库文件夹下的git bash中键入：`git pull`

## 9.我怎么删除不需要的分支或仓库？
你可能想要删掉一些不需要的分支，在仓库文件夹下的git bash中键入：（这一步也可以直接在github上完成，但由于缓存更新不及时的原因不推荐）
```
git branch -D 分支名        //删除本地分支
git push origin -d 分支名   //删除远端分支
```
当一个任务完成或废弃后，对应的仓库也便可以删除了，在Github中完成仓库删除操作。

## 10.注意事项
- 如果git push失败，很有可能是你在修改仓库并上传之前已经有人提前上传了新版本的仓库，此时需要先git pull获取最新的仓库后处理冲突再将写好的给git push，为了避免这一现象，请养成**在写新东西前主动进行一次更新的习惯**
- 组织中的所有人都具有**最高权力**，因此切记**不要做一些风险操作，进行更新/删除操作前请一定仔细确认，尤其不要随便删除别人的分支和随意覆盖main分支**
